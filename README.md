# Rail-ETA Intelligence

Prototype for **SIH 2026 · PS 26028 — Dynamic Forecast of ETA for Coaching Trains**.

A railway-side prediction layer: it forecasts station-level arrival times, quantifies
uncertainty, explains every revision, and decides when a change is worth broadcasting.

```bash
npm install
npm run dev
```

## What is real

The prediction engine runs in the browser but is not mocked. It performs:

- **Per-hop prediction** — separate run-time and dwell heads, composed forward, so
  per-station ETAs and compounding uncertainty fall out of the structure.
- **95% conformal intervals** — calibrated by split conformal on held-out journeys.
  Measured coverage is 95.3% against a 95% nominal. The confidence level is fixed;
  the *window* widens when the model is less sure.
- **Exact Shapley attribution** — 64 model evaluations over six feature groups on the
  difference between two predictions. Contributions sum exactly to the net change.
- **Deterministic propagation** — a declared block produces queue delays by priority
  and headway, which feed back as model features.
- **Significance policy** — dead-band scaled to interval width, two-cycle hysteresis,
  asymmetric thresholds, cooldown, critical-severity bypass.

## Measured (held-out, 2,600 journeys)

| | Model | Naive (schedule + delay) |
|---|---|---|
| MAE | 1.13 min | 4.14 min |
| RMSE | 2.87 min | 10.80 min |
| P90 | 2.27 min | 8.66 min |

72.8% MAE improvement. Error by horizon: 0.43 min at 0–30 min, 12.16 min at 240 min+.

## Fleet

3,443 daily services across three categories sharing one engine and one section graph:

- **Reserved** — 24 mail/express/superfast on CSMT–Pune, MMCT–Ahmedabad, LTT–Bhusaval
- **Unreserved** — suburban locals on Western, Central, Harbour (both arms),
  Panvel–Goregaon through services, Trans-Harbour
- **Metro** — Metro 1, 2A/7, 3

Routes are materialised lazily; only services inside the live window carry state.
Fifteen physical interchanges reconcile the codes the same place carries on different
lines — Dadar is `DR` on the mail line, `DDR` on Western, `DDRC` on Central and
`DDRM` on Metro 3.

## Screens

- **Control room** — searchable board (number, name, line, any station), category and
  status filters, per-train forecast scrubbers
- **Plan a journey** — pick an origin and destination, get direct services and
  one-change options, each leg forecast with its 95% window. Connections carry a
  **connection probability** read off the same residual distribution that sets the
  intervals, so a tight change behind an uncertain service is flagged even when the
  timetable says it works
- **Train detail** — station-by-station forecast, change attribution waterfall,
  prediction trajectory against the naive baseline
- **Ops console** — declare a block or speed restriction, watch differentiated
  revisions propagate by priority and queue position
- **Model performance** — reliability diagram, error by horizon, condition, category
  and line, plus the live feedback loop

## Data

Running data is generated by a mechanism-based simulator over the real network
topology — Indian Railways does not publish historical actuals. Every geography-
specific quantity lives in `src/data/`; the engine reads it generically.

See the architecture document for the full data strategy and the sources to fetch.
